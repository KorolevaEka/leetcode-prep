# Длительность параллельного прогона

Регрессию гоняют на `runners` параллельных агентах. Известны длительности тестов `durations` (положительные целые, в минутах). Список режут на последовательные куски: первый агент берёт несколько первых тестов, второй — следующие подряд и так далее; порядок менять нельзя, а агент может остаться без тестов. Прогон закончится, когда освободится самый загруженный агент.

Напиши функцию `min_run_time(durations, runners)` — наименьшее время, за которое можно уложить прогон при лучшей нарезке.

## Пример

```
min_run_time([4, 9, 3, 6, 2], 3)  ->  11    # куски [4], [9] и [3, 6, 2]: нагрузки 4, 9 и 11
min_run_time([1, 2, 3, 4], 4)     ->  4
min_run_time([5, 5, 5], 1)        ->  15
```

## Ограничения

`1 <= runners`, список не пустой. Ожидается решение быстрее полного перебора нарезок.
