# Live Coding Trainings — дизайн

Дата: 2026-11-09. Автор требований: Катя (владелец проекта). Сейчас репозиторий называется `leetcode-prep`,
в рамках работы переименовывается в `live-coding-trainings`.

## Зачем

Тренажёр для подготовки к live coding на собеседованиях, в первую очередь для **QA automation**,
во вторую — для разработчиков. На таких собеседованиях проверяют две вещи: ясны ли основы
(циклы, коллекции, строки, простые алгоритмы) и умеет ли кандидат **написать тесты на свой код**.
Сайт прокачивает обе.

Сейчас это личный тренажёр Кати (Python + SQL, 2 задачи, локальный Docker + агент выдаёт задачи).
Цель — открытый ресурс по ссылке для внешних пользователей.

**Первый успех**: Катя показывает ссылку знакомому автоматизатору, он «тыкает» и проходит задачи
на разных языках, темах и уровнях — с ноутбука и с телефона — и всё работает.

## Цели

1. Лендинг с пояснением, для кого сайт и что умеет.
2. Четыре языка: **Python, SQL, TypeScript, Java**.
3. Задачи сгруппированы по **темам** и **сложности** (Easy / Medium / Hard), фильтры по теме и сложности.
4. Внутри темы задачи открываются **цепочкой** — следующая после решения предыдущей.
   Пользователь может сразу начать со сложного уровня (см. правило ниже).
5. Два вида задач: **«напиши код»** и **«напиши тесты»** (кроме SQL).
6. **Подсказки** — ключевые слова/конструкции во всех языках.
7. **Вход через GitHub**, прогресс и черновики видны с любого устройства. Счётчик «решено N из M» по языку.
8. Всё выполняется **в браузере**, без серверного запуска кода.

## Не цели (сейчас)

- Вход по email (бесплатный SMTP Supabase шлёт письма только участникам проекта; нужен свой SMTP — позже).
- Английский интерфейс и условия — пока только русский.
- Рейтинги, лидерборды, обмен решениями, комментарии, админка.
- Серверное выполнение кода.
- 150 задач на язык — это **второй этап** (см. «Этапы»).

## Анти-цели (провал, даже если «технически работает»)

- Условия, скопированные с LeetCode дословно (авторское право). Только пересказ своими словами, свои примеры.
- Слово «LeetCode» в названии/брендинге сайта.
- Тесты задачи, которые пропускают неправильное решение, или мутанты, которые эталонные тесты не ловят.
- Подсказки, которые сбивают с толку: лишние или ведущие не туда.
- Сайт, которым невозможно пользоваться с телефона.
- Утечка секретов (в коде сайта только publishable-ключ Supabase).
- Чувствительные данные TaxDome в задачах. Можно брать только идеи сценариев автоматизатора.

## Решения Кати

- Название: **Live Coding Trainings**. Язык сайта: русский.
- Языки: Python, SQL, TypeScript, Java. Задачи полезны для автоматизации (и разработчикам).
- Темы и сложность, фильтр по теме, ранжирование по сложности, возможность сразу начать с Hard.
- Цепочка задач внутри темы: следующая открывается после решения предыдущей.
- Подсказки во всех языках: только релевантные, с явной пометкой, что использовать все не обязательно,
  это наводка для размышления. Клик вставляет слово в редактор, × убирает подсказку (как сейчас в SQL).
- Регистрация, чтобы заходить и с ноутбука, и с телефона. Supabase настроен Катей (см. «Ограничения»).
- **«Начать без входа»**: прогресс **не сохраняется**, уже решённые задачи недоступны, счётчик начинается с нуля
  при каждом заходе. Пользователь видит это предупреждение до того, как начать.
- Счётчик прогресса вида **«3/150»** (решено / всего задач в языке).
- Задачи пересказаны своими словами; часть — свои, по мотивам опыта автоматизатора (без чувствительных данных).
- Первый релиз: **по 2–3 задачи в каждой теме**, все темы и уровни; до 150 на язык — следующим шагом.
- **Публиковать сразу**, без ревью Кати перед выкладкой: она смотрит на живом сайте и присылает правки.
  Пушим в `main` по мере готовности, сайт должен оставаться рабочим после каждого пуша.
  Защита — CI-проверка задач перед деплоем.
- **Как можно проще и бесплатно.** Это бесплатный полезный проект: только бесплатные тарифы
  (GitHub Pages, GitHub Actions, Supabase Free, CheerpJ Community), никаких платных сервисов.
  Если выбор есть, берём более простое решение.
- **Лицензия: MIT** на весь репозиторий (код и задачи), файл `LICENSE` с автором Катей.

## Решения Claude (Катя может оспорить)

- **Вход через GitHub OAuth** (аудитория — инженеры), через Supabase Auth.
- **Правило цепочки**: внутри темы задачи упорядочены. Первая задача **каждого уровня** в теме открыта сразу.
  Остальные открываются после решения предыдущей задачи того же уровня. Так «начать с Hard» возможно,
  а внутри уровня — по порядку. У гостя разблокировка работает в рамках текущего визита.
- **Тема «напиши тесты»** проверяется мутационно: тесты пользователя должны **пройти** на эталонной
  реализации и **упасть** на каждом мутанте (специально сломанной версии). Результат вида
  «поймано 4 из 5 багов; пропущен: пустой список». Задача засчитана, если пойманы все мутанты.
  Код, который тестируют, — готовая функция, которую сайт показывает в задаче. Своё решение из прошлой задачи
  не используется: тогда эталон и мутанты не определены.
- **Синтаксис тестов похож на настоящие инструменты**: pytest (Python), Jest-подобный `test`/`expect` (TypeScript),
  JUnit 5 `@Test` + `Assertions` (Java). Как это реализовать (настоящая библиотека или совместимое подмножество),
  решает исполнитель, если синтаксис узнаваем для автоматизатора.
- **Запуск в браузере**: Python — Pyodide + pytest в Web Worker (как сейчас); SQL — PGlite (как сейчас);
  TypeScript — компилятор TypeScript в браузере, выполнение в Web Worker; Java — CheerpJ (см. «Риски»).
  У всех языков есть таймаут на зацикливание: сейчас 10 с для Python, без прерывания вкладки.
- **Эталонные решения и мутанты** лежат в репозитории (он публичный — подсмотреть можно, принимаем).
  В CI перед деплоем каждая задача автоматически проверяется: эталон проходит тесты, каждый мутант ловится
  эталонными тестами задачи «напиши тесты». Деплой не идёт, если проверка упала.
- **Мутанты у всех задач, не только у «напиши тесты».** У каждой задачи «напиши код» есть ≥2 мутанта
  (типичные ошибки). CI проверяет, что тесты задачи их ловят: так анти-цель «тесты пропускают неправильное решение»
  проверяется автоматически.
- **TypeScript проверяется с типами**: полный `tsc` с `lib.*.d.ts` в воркере. Ошибка типов — задача не решена,
  вывод показывает диагностику. Тема «типы и обобщения» может проверять типы на этапе компиляции
  (например, через `@ts-expect-error`).
- **Гость**: всё в памяти страницы. Перезагрузка стирает прогресс и черновики, `localStorage` для гостя
  не используется. Если гость входит через GitHub посреди визита, решённое за этот визит переносится в аккаунт.
- **Переименование репозитория** — первым шагом: Катя согласилась на новое имя, а Supabase уже настроен
  на новый адрес. Две текущие задачи (Two Sum, Combine Two Tables) переписываются под новые правила или заменяются.
- **Черновики** залогиненного пользователя синхронизируются в Supabase (колонка `code`).
- **Локальный режим** (Docker, `./run`, агент «дай задачу / проверь» по `CLAUDE.md`) остаётся как инструмент Кати
  для авторинга задач. `CLAUDE.md` обновляется под новую структуру задач, темы и языки.

## Предлагаемые темы (Claude, ~8 на язык; исполнитель может уточнить)

Каждая тема — Easy → Medium → Hard. В первом релизе 2–3 задачи на тему. Хотя бы в части тем на одном уровне
должно быть 2 задачи, чтобы цепочку было видно уже в первом релизе.

- **Python**: строки; списки и циклы; словари и множества; сортировка и поиск; два указателя и скользящее окно;
  рекурсия; разбор данных (логи, JSON, CSV); **напиши тесты**.
- **TypeScript**: строки и массивы; объекты и Map/Set; типы и обобщения (generics); промисы и async
  (ретраи, таймауты, ожидание условия); обработка данных (группировка, сравнение JSON-ответов);
  алгоритмы (стек, очередь, поиск); парсинг (URL, query-строк, селекторов); **напиши тесты**.
- **Java**: строки и StringBuilder; массивы и циклы; коллекции (List/Map/Set); Stream API; ООП и интерфейсы;
  исключения и валидация; алгоритмы; **напиши тесты**.
- **SQL**: SELECT и фильтрация; JOIN; агрегаты и GROUP BY/HAVING; подзапросы; оконные функции;
  даты; NULL и CASE; поиск аномалий в данных (дубликаты, пропуски — как в проверке данных тестировщиком).

QA-флейвор задач, на который можно опираться: разбор логов, ретраи и ожидания, сравнение ответов API,
валидация данных, даты и таймзоны, генерация тестовых данных, дедупликация, отчёты о прогонах тестов.

## Что видит пользователь

- **Лендинг** (`/`): название, для кого (QA automation и разработчикам перед live coding), что умеет:
  4 языка, темы и уровни, задачи «напиши тесты» с проверкой мутантами, подсказки, запуск в браузере без установки,
  прогресс на ноутбуке и телефоне. Кнопки **«Войти через GitHub»** и **«Начать без входа»**
  (с предупреждением про несохраняемый прогресс). Кредит **«Built with CheerpJ»** где-то на сайте (условие лицензии).
- **Каталог**: вкладки языков со счётчиком «N/M», фильтры по теме и сложности, темы с задачами-цепочками
  (видно решено / открыто / закрыто).
- **Задача**: как сейчас — условие, подсказки (с пометкой «необязательно, это только наводка»), редактор
  (CodeMirror: подсветка, автоотступы), запуск ⌘↵, вывод тестов. У SQL — схема таблиц и данные.
  У задач «напиши тесты» — показан тестируемый код, результат «поймано N из M мутантов».
- Работает на телефоне (вёрстка уже адаптивная — сохранить).

## Риски

- **Java в браузере.** CheerpJ (Community-лицензия бесплатна для некоммерческого open source при загрузке с их CDN
  и кредите «Built with CheerpJ») запускает JAR-файлы. Компиляция исходников в браузере в документации не описана.
  Первый шаг исполнителя — **спайк**: javac (из JDK-рантайма CheerpJ) или Eclipse ECJ (standalone jar) под CheerpJ,
  компиляция и запуск теста. Если не получится, вернуться к Кате до остальной работы по Java.
- Первый запуск Java и Python тяжёлый (десятки МБ). Показывать прогресс загрузки, на телефоне проверить отдельно.
